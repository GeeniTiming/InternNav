# Fixed train-split native-failure discovery

The next step after case 15 is to test whether similar native failures recur on
a small, fixed train subset. No physical recovery or training runs in this tool.
It reuses the unchanged native cache_pilot.py runner with cache disabled and
native debug recording enabled.

## Selection and stopping rule

Before observing any outcomes, lock 24 different reference-route groups from six
train scenes. Each scene contributes four groups. Same-scene trajectory IDs and
equal reference polylines (rounded to 0.1 mm) are unioned, including transitive
aliases; choose one instruction variant per resulting group.

Use deterministic SHA-256 ordering with selection seed 20261026. Each batch
contains two route groups per scene, for 12 episodes. The policy uses its
existing per-episode seed rule with base 20261024. Model, image history,
motion parameters and episode budgets remain native.

Run batch 1 first:
- If at least three native failures occur, stop and review up to the first five
  failures in the predeclared plan order.
- If fewer than three fail, run the already fixed batch 2 once.
- Stop after batch 2 even if fewer than three fail. Do not resample until a desired
  failure count appears.

Retain all outcomes, including successes and unselected failures. Different
reference-route groups can overlap spatially and share scenes; they do not
establish statistical independence. Train observations are exploratory
development evidence and not held-out benchmark performance.

## Run in the existing checkout

~~~bash
cd /home/geenitiming/InternNav
conda activate internnav_habitat
git pull --ff-only

PYTHONPATH="$PWD" USE_TF=0 CUDA_VISIBLE_DEVICES='' \
  python -m unittest discover -s tests/unit_test \
  -p test_train_failure_probe.py -v

PYTHONPATH="$PWD" USE_TF=0 CUDA_VISIBLE_DEVICES='' \
  python scripts/eval/train_failure_probe.py prepare \
  --run-dir data/train_recovery_probe_01
~~~

Preparation is CPU-only. It reads the original split-templated native config,
switches only a generated copy of the Habitat dataset config to train, and locks
both 12-episode subsets before any rollout. It uses the existing train annotations,
scenes and checkpoint. It enables debug video for failures and successes without
editing original configuration files. Existing experiment code/manifests remain
unchanged. All new directories are create-only.

One native evaluator/model is initialized per batch; its 12 episodes execute
sequentially. This is not a GPU inference batch-size change.

~~~bash
set -o pipefail

PYTHONPATH="$PWD" USE_TF=0 CUDA_VISIBLE_DEVICES=0 \
  python -u scripts/eval/train_failure_probe.py run \
  --run-dir data/train_recovery_probe_01 --batch 1 \
  2>&1 | tee data/train_recovery_probe_01/batch01_console.log

PYTHONPATH="$PWD" USE_TF=0 CUDA_VISIBLE_DEVICES='' \
  python scripts/eval/train_failure_probe.py report \
  --run-dir data/train_recovery_probe_01
~~~

If the report status is NEED_DECLARED_RESERVE, run the fixed reserve:

~~~bash
PYTHONPATH="$PWD" USE_TF=0 CUDA_VISIBLE_DEVICES=0 \
  python -u scripts/eval/train_failure_probe.py run \
  --run-dir data/train_recovery_probe_01 --batch 2 \
  2>&1 | tee data/train_recovery_probe_01/batch02_console.log

PYTHONPATH="$PWD" USE_TF=0 CUDA_VISIBLE_DEVICES='' \
  python scripts/eval/train_failure_probe.py report \
  --run-dir data/train_recovery_probe_01
~~~

The wrapper refuses batch 2 when completed batch 1 already has three failures.
An incomplete batch is not summarized as a complete cohort. Neither cache arm
generated by the reused pilot preparation is part of this protocol; run only
the control via train_failure_probe.py.

## Outputs

- plan.json: all 24 predeclared keys, route groups and batch assignments.
- cohort_manifest.json: original/generated input and tool hashes.
- batch_01/control/ and batch_02/control/: original native traces, progress and summaries.
- batch_01/video/ and batch_02/video/: all native debug videos.
- report_batch_01.json or report_batch_02.json: complete native outcome denominator,
  plus selected failure cases and original video paths.
- cases/SCENE_EPISODE/: copies of selected annotations, outcomes and action arrays.
  No video rerun or semantic labeling is needed to produce these exports.

Upload the compact report output first. Subsequent visual review should separate
route/room selection, local execution and stopping errors before prescribing a
physical correction. The case15-specific recovery script must not be applied
to these episodes: its step, route and waypoints are deliberately locked.

CPU tests cover route deduplication, order/outcome-independent selection,
generated train-only configs, stopping rules, success denominators, exact case
metadata, missing videos, malformed traces, source preservation and hash checks.
Actual Habitat/GPU execution must be verified on the server.
